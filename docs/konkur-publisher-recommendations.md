# Online-only Konkur publisher recommendations

The counselor can optionally select **one publisher per plan item** for Konkur `lesson`, `practice_tests`, `review` and `homework` activities. The predefined list is Gaj, Kheili Sabz, Nashr-e Olgoo, Mobtakeran, Mehr-o-Mah, Ghalamchi, Nashr-e Daryaft, Moshaveran-e Amoozesh and Montasheran (shown in Persian in `lib/recommended-publishers.ts`). “Other publisher” accepts a publisher name, not a book title. School/final-exam items, textbook reading, class/offline class, exams/simulations/analysis, notes, summaries and general activities cannot carry a recommendation. Existing items default to none.

The recommended publisher is displayed next to its item in the **on-site** daily/weekly student panel and counselor report. Both print route projections omit the column, and `PrintWeeklyPlan` does not render it. A regression test passes publisher data directly to the print component and checks that it still does not appear.

Migration `085_konkur_recommended_publisher.sql` adds one nullable, constrained column to the existing RLS-protected items table and one authenticated-only `save_weekly_plan_v6` RPC. The RPC delegates all old ownership/assignment/locking/exam-link rules to v5, then associates recommendations with the newly saved items by sort order and day in the same transaction. The student dashboard RPC retains its identity, activation, publication and pagination rules and adds the publisher to the on-site projection. No new public table or account/data deletion is involved.

The migration was applied and checked on the connected nova Supabase project before this code is deployed: column, constraint, v6 execute grant (authenticated only), and student RPC projection exist. Existing non-null recommendation count was zero. Roll out the app **after** the migration. Validation uses disposable PostgreSQL and mocked rendering only: no real user login, plan save or print on production has been tested. Live behavior depends on the application deployment.
