# Actual minutes in student plan boxes

Students can enter the actual number of minutes for any non-`practice_tests` activity (1–1440 whole minutes) and the number of tests for `practice_tests` (1–5000). The existing checkbox records the entry; an already checked box can be edited by changing its value and leaving the field. Unchecking removes the recorded progress. Future boxes and counselor read-only views are unchanged. No SMS or exam submission is involved.

Migration 086 adds nullable `completed_minutes` to the existing completions table and a four-argument progress RPC. The old three-argument RPC remains available during rollout. The new RPC invokes the old student/active/published/own-plan/date validation in the same transaction, checks the activity-specific field, and preserves `checked_at` on edits. It uses an explicit authenticated EXECUTE grant; it creates no new public table. The student paged dashboard RPC and counselor report read include the new value. Migration 086 was applied and verified on the connected production Supabase project: column exists, authenticated can execute the new RPC, anonymous cannot, the dashboard projects minutes and no recorded minutes exist yet. Deploy the application after the migration; the application was not deployed by this commit.

Existing completed non-test boxes have `completed_minutes = null`; they stay checked and the reports use their planned duration as a **legacy estimate**, never display it as entered actual time. For new non-test boxes, reports and counselor hours use actual minutes; for tests they continue to estimate time from the completed/target test ratio. Fulfillment is capped at 100% even if actual study exceeds the planned duration, while the recorded time remains uncapped. The student's printable plan still has only planned activities and no progress input or actual minutes.

Validation: disposable PostgreSQL RPC test checks permissions, past/future, activity-specific bounds, rollback, editing and first-tick preservation. Paged dashboard projection checks the value under the existing RLS. Mock DOM test checks student controls without real writes. TypeScript, targeted lint and build should pass before release. No production account or SMS needs to be used to test this feature.
