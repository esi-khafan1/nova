# Planner rebuild: foundation and outstanding integration

The counselor approved the light Nova-style mockup in `planner-preview/` and requested all features together, with any seven-day start date. A draft must autosave without altering what the student sees until explicit publication. Existing plans, completion records, exam links, makeup boxes and both daily routines must remain intact.

## Current status

The new planner is **not connected to the app or ready for use**. The grid, autosave/session coordinator, analysis, review, topic suggestion modules and three-section print suite are isolated components/helpers. The print suite accepts an already authorized plan snapshot and review records; it does not load them itself and must not be wired to a route until the rest of the integration is ready. Migration `118_planner_private_drafts.sql` provides a private working-copy store; `119_planner_atomic_publish.sql` delegates publication to the existing save chain after checking draft revision and base plan; `120_planner_personal_presets.sql` stores counselor-owned presets; `121_planner_reviews.sql` provides published-item review checkmarks; `122_planner_published_extras.sql` publishes extra week/item data atomically; `123_planner_review_history.sql` retains checkmarks through item replacement or changes. The unfinished publisher is **not executable by authenticated users**: migration 119 starts fail-closed and 124 revokes any old grant defensively. Migration 125 is a candidate guard for concurrent plan saves and designer box assignment. Migrations 118–125 have **not been applied to any project**. No old plan is rewritten. The prototype images are static design references, not functional screens.

## Release-blocking exam race found in an isolated fixture

The latest `save_designer_exam` from migration 084 validates selected plan box IDs before locking the exam and does not verify its final update count. The existing v9 chain can replace a future box between those steps. In `tests/planner-concurrency.postgres.cjs`, real PostgreSQL sessions reproduce this ordering: the designer RPC returns successfully, but the selected old box has been replaced and the exam has no link to the new one. This is a local synthetic reproduction, not proof that any real plan or exam has been affected.

Migration 125 is a candidate fix: it rechecks selected boxes under row locks, uses a nonblocking retry if those rows are busy, and locks plan items before the legacy v5 link snapshot (with a nonblocking student-lock check to prevent lock-order deadlocks). Local multi-session tests cover the reproduced interleaving, the opposite ordering, a cached v5 writer, a busy item, and retained progress; existing designer behavior and deliberate removal also pass locally. The guard is **not deployed** and does not by itself resolve ambiguous same-day/subject/chapter box identities or establish the publisher's missing validation. The new publisher remains disabled. Fixture-only grants do not signal readiness.

## Required before release

- `lib/planner-plan-adapter.ts` converts the existing plan shape and explicitly loaded published extras into a seven-day grid and builds a private draft snapshot. It retains opaque metadata, exact topic JSON, historical source IDs and past-day editor state, and never reuses source IDs on a copy. `lib/planner-draft-restore.ts` reconciles a saved draft with freshly loaded progress, exam links, plan version and date, reporting conflicts without dropping edits. `lib/planner-publication-preflight.ts` connects this check to the draft session, which durably saves the recomputed snapshot before publishing its revision. Isolated browser and database fixtures test these pieces, but **none is connected to the real builder yet**. The real UI must load fresh authorized data, display and resolve conflicts, always install the preflight, handle navigation and snapshot-size failures without discarding edits, and refresh the student/plan state after publication.
- Connect a responsive seven-day editor to the existing student selection, planning data and print/report paths; retain all existing subject, exam, simulation, makeup, routine, completion and protected-day behavior.
- Integrate draft loading, the serialized autosave session, existing server-side validation and the atomic publication RPC. The transport calls the RPC directly: before use, establish that all validations enforced by `saveWeeklyPlanCore` also run authoritatively for publication (not merely in the browser). Ensure the UI handles changed live plans and progress since editing began. Never clear or publish a draft after a failed or conflicting save.
- Connect preset storage and implement ready-block, personal-pattern and week-template interfaces. Connect topic suggestions and review completion (including the published-history RPC, historical toggles and draft previews). Carry prior-week reviews into the selected date range; exclude exam and makeup activities from automatically generated study reviews. On publication, supply each persisted item's `sourceItemId` even when v9 requires `id: null` for a future item. Unchanged reviews then transfer with their timestamp; changed/removed source reviews remain separately visible as history. Integrate and test this behavior end to end, including legacy clients.
- Implement keyboard and touch-accessible movement, day copying, undo, editing and responsive desktop/mobile layouts, without bypassing locks on completed or past activities.
- Integrate the isolated `PlannerPrintSuite` with authorized published-plan metadata, review sources and history (and the draft editor's own snapshot as appropriate). The existing print route is intentionally unchanged. Browser tests cover selection, mobile/desktop and a small real three-page PDF, while the legacy print regression covers a dense week; additionally verify dense analysis/review pages, long text and production data in the integrated flow. Preserve the existing student/print data and routine behavior.
- Construct and verify the full topic/page bank by book edition. Do not fabricate missing topics or page ranges, and do not redistribute copyrighted book files. Document source, edition and verification for each entry.
- Review and integrate the candidate designer/plan concurrency guard, resolve different boxes with identical subject/chapter inheriting an unintended exam link, and add integrated end-to-end tests for simultaneous exam selection, publication and deliberate removal. Do not simply re-grant the publisher or silently remove exam boxes to make the tests pass. A reviewed migration to re-enable the publisher is required only after the full validation and data-preservation tests succeed.
- Test authorization, save/reload and navigation in the integrated browser at desktop/mobile sizes, actual PDF output, lint, TypeScript and build. A disposable multi-session PostgreSQL test exercises concurrent publish/autosave, completion and review ticks through the actual v9→v3 save chain (including current v4/v5). Apply any database migration only when the integrated change is ready and verified.
