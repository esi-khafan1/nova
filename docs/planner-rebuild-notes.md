## Release-blocking exam race found in an isolated fixture

The latest `save_designer_exam` from migration 084 validates selected plan box IDs before locking the exam and does not verify its final update count. The existing v9 chain can replace a future box between those steps. In `tests/planner-concurrency.postgres.cjs`, real PostgreSQL sessions reproduce this ordering: the designer RPC returns successfully, but the selected old box has been replaced and the exam has no link to the new one. This is a local synthetic reproduction, not proof that any real plan or exam has been affected.

Migration 125 is a candidate fix: it rechecks selected boxes under row locks, uses a nonblocking retry if those rows are busy, and locks plan items before the legacy v5 link snapshot (with a nonblocking student-lock check to prevent lock-order deadlocks). Source-aware payloads now restore future exam links by original item ID; legacy payloads reject ambiguous matching instead of spreading a link to duplicate boxes. Retained IDs never transfer a link to a duplicate. Disposable database tests exercise source identity, explicit removal and rollback on ambiguous legacy input; the real v9 publication chain and multi-session race fixture also pass locally with this candidate. The guard is **not deployed** and does not establish the publisher's missing validation. The new publisher remains disabled. Fixture-only grants do not signal readiness.

## Draft discard after a failed autosave

The private editor now exposes an explicit, confirmed discard/reload action when autosave fails. It waits for any in-flight save, deletes only the last acknowledged revision with the server's compare-and-swap, and refuses to delete a newer remote draft. If the first save was not acknowledged, it checks the server and only allows local discard when no remote draft exists; a failed check or an existing remote draft leaves the editor intact. This is still behind the release gate and does not activate the publisher.
