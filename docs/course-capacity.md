# Course capacity status

The super-admin course settings have three global states: sale, reservation and sold out. Migration 116 retains the existing sale/reservation value and defaults sold-out to false; it does not switch production to sold out. Apply the migration before deploying this web version. The v1 public offer RPC remains available for an older web version, but only the new web version can display and set the third state.

When sold out, the catalog identifies the state, details pages do not offer enrollment, and the student enrollment page omits the payment information, Telegram receipt alternative and submission form. It tells students not to pay. Ordinary account information, active services and existing pending registrations are not deleted. Admin receipt handling and review/activation of existing requests remain independent.

The server action checks status before uploading. The database wraps the original registration RPC without changing its validation, and locks the singleton status row while submitting, so a stale page cannot submit after the status change has committed. The old implementation is private and not executable by API roles. The student's receipt-upload policy also checks the state; cleanup of unused uploads and the admin upload policy are unchanged. If the status cannot be loaded, the new enrollment page/action fail closed. Existing open pages or people who already know the bank account or Telegram address cannot be prevented from making an external transfer or sending a message; no online payment gateway is controlled by this site.

Tests: `node tests/course-capacity-sql.test.cjs` exercises status, privileges, receipt RLS, stale requests and reopening in disposable PGlite. `node tests/one-month-registration.test.cjs` exercises original registration guards through the new wrapper. `node tests/course-capacity-ui.test.cjs` and `node tests/registration-verified-phone.test.cjs` test the page/action with mocks, including pending and profile-only paths. No actual registrations, payments, uploads or accounts were changed during validation. Deployment and live browser behavior are separate from the database migration.
